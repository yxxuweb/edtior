这是一个非常关键且正确的决策。对于低代码编辑器核心库而言，**引入不可变状态 (Immutable State) 是“必选项”，而非“可选项”。**

### 为什么必须引入？

1. **Undo/Redo 的基石**: 编辑器最核心的体验就是撤销重做。如果使用可变对象（直接修改），你需要手动保存对象的深拷贝副本，内存消耗大且容易出错。使用不可变数据（如 `Immer`），历史记录只需要保存状态的引用，天然实现了“结构共享”，内存占用极低。
2. **变更检测性能**: 渲染层（尤其是 React）需要快速判断组件是否需要重绘。不可变数据允许使用 `oldState === newState` 的 O(1) 级比较，极大提升大型页面树的渲染性能。
3. **副作用隔离**: 避免了“在 A 处修改对象，意外导致 B 处数据变动”的 Bug，这在复杂的节点树操作中非常常见。

### 实施方案

我将正式引入 **Immer** 作为状态管理的核心库，并采用 **单向数据流** 模式。

#### 1. 架构文档更新 (ARCHITECTURE.md)

* **技术选型**: 明确引入 `immer`。

* **数据流设计**: 定义 `Action` -> `Reducer (produce)` -> `New State` 的流向。

* **状态模型**: 明确 Node 和 Document 的状态必须是 Plain Object，且不可变。

### 示例代码预览

```javascript
import { produce } from 'immer';

class Node {
    setProp(key, value) {
        // 核心：基于当前状态产生新的不可变状态
        const nextState = produce(this.state, draft => {
            draft.props[key] = value;
        });
        
        // 只有新旧状态引用不同时，才触发更新
        if (nextState !== this.state) {
            this.state = nextState;
            this.emit('change', this.state);
        }
    }
}
```
